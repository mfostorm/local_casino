# HTTPS через Caddy и nip.io

Этот конфиг предназначен для **машины, на которой запущено приложение**.
Caddy принимает HTTPS на порту 443 и передаёт HTTP и WebSocket на порт 3000.
Он автоматически получает и продлевает сертификат Let's Encrypt; вручную
выгружать сертификат и приватный ключ в репозиторий не нужно.

## Что требуется для публичного сертификата

- Реальный публичный IPv4 сервера или домашнего роутера.
- Адрес вида `casino.<PUBLIC_IPV4>.nip.io`, который разрешается в этот IPv4.
- Входящий TCP-трафик на **80 и 443**, доходящий до Caddy.
- Исходящий HTTPS-доступ Caddy к Let's Encrypt, включая
  `acme-v02.api.letsencrypt.org`, и рабочий DNS.

nip.io предоставляет DNS, но **не пробрасывает порты и не создаёт туннель**.
Адрес 192.168.x.x, адрес 10.x.x.x, localhost и IP исходящего облачного прокси
не подходят для публичной проверки владения доменом. При домашнем подключении
потребуется перенаправление TCP 80/443 с роутера на компьютер и разрешение этих
портов в брандмауэре. При CGNAT нужен публичный IP от провайдера либо VPS/туннель.
Не открывайте для этого административный порт Caddy 2019.

## Windows / PowerShell

Установите Caddy из [официального источника](https://caddyserver.com/docs/install)
и проверьте `caddy version`. Откройте терминал в корне проекта.

Сначала соберите и запустите приложение:

```powershell
npm ci
npm run build
$env:NODE_ENV = "production"
npx tsx server/index.ts
```

В **другом терминале**, в той же папке, укажите полный настоящий домен
вместо примера. `203.0.113.10` ниже — документационный адрес, он не работает:

```powershell
$env:CASINO_DOMAIN = "casino.203.0.113.10.nip.io"
caddy validate --config .\Caddyfile --adapter caddyfile
caddy run --config .\Caddyfile --adapter caddyfile
```

Оставьте оба процесса запущенными. Если Caddy не может привязать 80/443,
проверьте, не заняты ли порты IIS или другим сервером и достаточно ли прав.
Не отключайте брандмауэр целиком; разрешите только необходимые входящие порты.

## Linux / VPS

Установите Caddy по официальной инструкции для вашей системы. Запустите
production-сборку Node.js 24+ на порту 3000. Для ручного запуска Caddy
в терминале, которому разрешено слушать 80/443:

```sh
export CASINO_DOMAIN=casino.203.0.113.10.nip.io
caddy validate --config ./Caddyfile --adapter caddyfile
caddy run --config ./Caddyfile --adapter caddyfile
```

Здесь также требуется заменить документационный IP своим публичным адресом.
При использовании системной службы Caddy задайте `CASINO_DOMAIN` именно
в окружении службы, а не только в интерактивном shell, либо впишите конкретный
домен в Caddyfile, установленный для этой службы. Сохраните каталог данных
Caddy между перезапусками: в нём находятся сертификаты и аккаунт ACME.

## Проверка

До запуска Caddy убедитесь, что Node отвечает на локальный запрос:

```sh
curl http://127.0.0.1:3000/api/health
```

После запуска проверьте DNS домена, затем с другого подключения к интернету
откройте `https://<ВАШ_ДОМЕН>/api/health`. Должен вернуться JSON с `ok: true`,
а браузер должен доверять сертификату. HTTP автоматически перенаправляется
на HTTPS. Открывайте приложение по этому HTTPS-адресу перед копированием
приглашений: QR-коды и ссылки будут использовать тот же домен.

`caddy validate` проверяет конфигурацию, но **не подтверждает получение
сертификата**. Успешную выдачу проверяют по журналу Caddy и реальному
HTTPS-подключению. Если ACME-проверка не проходит, сначала исправьте DNS,
доступность 80/443 и сетевую политику; повторные перезапуски без исправления
причины могут привести к ограничениям частоты выдачи.
